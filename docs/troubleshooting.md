# 트러블 슈팅 및 렌더링 최적화 (Troubleshooting)

이 문서는 개발 과정에서 직면했던 문제점과, 이를 해결하기 위해 어떤 고민을 거쳐 코드를 개선(리팩토링)했는지 기록한 문서입니다.

## ⚠️ 문제 상황: 불필요한 렌더링 (Too many re-renders)
Vanilla JS에서는 DOM 요소 하나하나를 직접 타겟팅해 조작했지만, React로 넘어오면서 상태(State)가 변경될 때마다 하위 컴포넌트 전체가 다시 렌더링되는 성능 문제가 발견되었습니다.
특히 상위 컴포넌트인 `App.jsx`에서 `text` 입력 상태나 탭 전환 같은 가벼운 동작을 수행할 때마다, 수십 개의 항목을 가진 `TodoList` 전체가 리렌더링되는 비효율이 발생했습니다.

## 💡 해결 과정 및 최적화 기법 도입

### 1. `React.memo`를 통한 컴포넌트 메모이제이션
개별 아이템인 `TodoItem.jsx` 컴포넌트를 `React.memo`로 감싸주었습니다.
이를 통해 자신에게 전달되는 `props`(todo 항목 내용, 삭제 함수 등)가 변경되지 않는 한, 부모 컴포넌트가 렌더링되더라도 `TodoItem`은 리렌더링을 방어하게 되어 성능을 개선했습니다.

### 2. `useCallback`을 통한 함수 참조 유지
하지만 `React.memo`를 적용했음에도 불구하고 필터 상태가 변할 때 리렌더링이 발생했습니다.
원인은 `App.jsx`가 렌더링될 때마다 `toggleTodo`, `deleteTodo` 같은 핸들러 함수들이 새로 생성되어 `props`로 전달되었기 때문이었습니다.
이를 해결하기 위해 `useCallback` 훅을 사용해, 의존성 배열에 아무것도 넣지 않거나 필요한 값만 두어 **함수의 참조값을 고정**시켰습니다.

### 3. `useMemo`를 통한 파생 상태(Derived State) 최적화
마지막으로, 사용자가 달력 날짜를 변경하거나 상태 필터를 바꿀 때, 기존에는 `getFilteredTodos()` 함수가 렌더링 사이클마다 매번 배열 전체를 순회(filter)하며 계산했습니다.
이를 `useMemo`로 감싸 `[todos, currentFilter, selectedDate]` 중 하나라도 변경되었을 때만 계산을 수행하도록 최적화했습니다.

## 🎯 결론
React의 단방향 데이터 흐름의 특성을 명확히 이해하고, `memo`, `useCallback`, `useMemo`라는 세 가지 최적화 도구를 적절한 곳에 투입함으로써, 기능은 완벽하게 동작하면서도 성능적으로 매우 쾌적한 앱을 완성할 수 있었습니다.
