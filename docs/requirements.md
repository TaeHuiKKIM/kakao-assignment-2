# 요구사항 정의서 (Requirements)

## 1. 목적
기존 Vanilla JS 환경에서 작동하던 Todo 앱을 React 생태계로 성공적으로 마이그레이션하여, 유지보수성과 확장성을 높인 컴포넌트 기반 아키텍처로 개선합니다.

## 2. 주요 기능 및 요구사항 (Functional Requirements)

### 2.1 Todo 핵심 관리 (CRUD)
- 사용자는 텍스트 입력 후 'Enter' 키 또는 '추가' 버튼을 통해 Todo를 등록할 수 있어야 한다.
- 등록 시 공백(빈 문자열)에 대한 예외 처리가 이뤄져야 하며, 2초간 경고 메시지가 노출되어야 한다.
- 각 Todo 항목은 '수정', '삭제' 버튼을 가지며, 수정 클릭 시 인라인 입력 폼으로 자연스럽게 전환되어야 한다. (prompt 금지)
- 체크박스를 통해 '완료' 상태를 토글할 수 있어야 한다.

### 2.2 필터링 기능 (Filter)
- 상단 탭을 통해 '전체', '진행 중', '완료' 상태 필터링을 지원해야 한다.
- 필터 조건이 변경되어도 로컬에 저장된 전체 데이터는 손실 없이 유지되어야 한다.

### 2.3 날짜 및 주간 뷰 연동 (Calendar)
- Todo 데이터는 생성 시 현재 '선택된 날짜(selectedDate)' 속성을 가져야 한다.
- 주간 뷰를 통해 좌우 버튼으로 주차를 이동하며 특정 날짜를 클릭해 선택할 수 있다.
- 선택된 날짜에 매칭되는 Todo 항목만 렌더링해야 한다.
- 각 날짜 아이템 하단에는 해당 날짜에 속한 Todo의 총개수를 뱃지로 표시한다.

### 2.4 데이터 영속성 (Persistence)
- 새로고침이나 브라우저 종료 후에도 데이터가 유지되도록 로컬스토리지를 연동해야 한다.

## 3. 비기능적 요구사항 (Non-Functional Requirements)
- **성능 최적화**: 렌더링을 최소화하여 성능 병목이 생기지 않도록 `React.memo`와 훅의 불변성을 보장한다.
- **가독성 및 재사용성**: UI와 비즈니스 로직(Custom Hooks)을 분리하여 각 컴포넌트의 책임을 단일화한다.
